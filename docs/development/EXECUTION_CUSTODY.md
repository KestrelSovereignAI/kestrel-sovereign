# Transaction-bound hosted execution custody

Core issue #3569 extends existing PostgreSQL advisory and native transaction
custody. This is a host authority contract, not a causation-derived permission.

Corpus-profile surveys and operator reindexing preserve original native control
before unreadable-table/zero-count fallbacks, batch splitting, failed-row
accounting or registry/parity success. Actual localhost SDK outputs, scoped
PostgreSQL vector writes and post-COMMIT release-ACK failures exercise these
producer boundaries, including the real model-preference callback wired to the
LLM service. A committed first-row failure cannot continue into a second row.
Ordinary availability failures retain their best-effort behavior and legitimate
bounded split retry. These are component/native proofs, not full Agent READY,
authenticated HTTP or public-provider acceptance. Explicit component DDL does
not certify startup migrations; legacy cross-schema migration probes are tracked
separately in #3673. Settings/CLI consumers and sibling context tools remain
under the cumulative review ledger, not cleared merely by these producer
tests. The task-list HTTP wrapper likewise propagates the identity
helper's original receipt instead of replacing it with an ordinary HTTP500.

Shared conversation history, selection, compaction, summary and stash producers
preserve original native control through their typed and generic availability
handlers. Context tools do the same before producing ToolResult errors, empty
history or dry-run success. Native tests exercise actual scoped PostgreSQL reads,
metadata/summary/saved-item writes and locally served SDK summary responses; a
committed first mutation cannot continue into another row or an audit write.
Compatibility carriers explicitly retain the observed original receipt, not an
invented acknowledgement. Healthy mark/stash/list/pop operations retain the
stored rows without model requests. Stash JSON encodes the known native
created_at datetime without mutating source rows or stringifying arbitrary
metadata. Component Agent projections still do not establish genesis/READY or
authenticated HTTP. Other cumulative lifecycle and settings/CLI findings remain
open until independently cleared.

Pre-turn Codex-thread compaction preserves that same original control before
either turn-entry caller can continue or reset the thread. Native component
tests traverse actual history reads, summary insertion and metadata updates;
the adapter occupancy is a declared cache input, not a live Codex session.
Embedding settings likewise observe the actual scheduled route-preference writer
before returning success and preserve its retained native outcome. Shared CLI
metadata, registry and active-profile reads and their reindex consumers preserve
control before missing-configuration or unavailable-count fallbacks. Ordinary
availability behavior remains unchanged. The complete settings operation also
observes profile writers scheduled during its asynchronous response echo, not
only the writer scheduled by the initial route update.

Embedding discovery/settings/parity HTTP consumers, persisted and runtime pin
application, reindex target resolution and both offline CLI resolution helpers
preserve canonical control before best-effort reconciliation, active-route
fallback, typed HTTP400/409 validation or ordinary HTTP500/refusal conversion.
Request-body readers also preserve an explicit native control carrier before
their ordinary malformed-body default. Ordinary unavailable providers and
invalid operator pins retain their prior compatibility behavior. The boundary
matrix runs actual scoped corpus/settings SQL, real local-SDK operations and
the original retired PostgreSQL lease denial at named consumer callbacks. The
three-dimensional fixture schema/configuration is an explicit component input,
not startup-migration or full deployed-schema acceptance. Transparent factories
use an explicitly borrowed usage database and independently retire constructed
services; this does not clear F63's default/private SDK lifetime inventory.

The existing database retirement owner retains finite original body, closer
and caller-withdrawal evidence together, including failure wrapping during
initialization. Physical close is joined before any receipt is returned;
retirement uncertainty still exposes the same database recovery owner. An
actual cancellation observed during that join cannot disappear just because
native control is stronger or the closer also fails. This uses the existing
canonical original-preserving composition, not another closer, replay grant
or an unbounded history of subsequent readers. CLI-owned SQLite workers and
the initialization closer are physically retired in the regression cases.
These changes remain subject to whole cumulative independent review; the
other open lifecycle, admission and provider findings are not waived.

Preference and modality persistence drains project each finite invocation's
original writer/observer evidence through a fresh explicit carrier after all
accepted writers join. Mandate-entry's outer drain observer preserves its own
withdrawal too. The service's long-lived strongest-writer latch remains
separate: later uncancelled readers receive the original native writer control,
not previous callers' cancellations or a growing observer history. Original
PG metadata writes/COMMIT/release, actual Agent callbacks, actual endpoint and
mandate bodies exercise preference draining; sibling SQLite writers exercise
the related modality consumer with declared compatibility receipts.

The outer service close-completion join also retains its finite observations:
two distinct drain observers can carry different actual withdrawals while
joining the same native writer. Selecting one strongest native receipt must
not discard those originals. This composition uses a fresh carrier; the
bounded writer latch and physical native close owners stay unchanged.

Bridge session, logging, initialization, status/history, tool enumeration and
HTTP availability consumers likewise propagate canonical control before
best-effort fallback or success. Native lease denials are delivered after real
PG/SQLite statements at explicit component callbacks; these tests do not claim
native lost-COMMIT or authenticated gateway acceptance. The healthy hour count
uses a bound UTC ISO cutoff matching persisted timestamps on both backends,
not SQLite-only SQL or a differently formatted text comparison.

Bridge stream teardown preserves both the interrupted serializer's original
carrier and its separate source owner's cleanup failure. The source owner's
own cancellation is not a substitute for the transport observer's withdrawal.
Request completion still waits for the actual source retirement and marks
uncertain cleanup abandoned; original retention never becomes a successful ACK.

Constitution/doctrine audit, anchor, governing-text and pre-turn consumers
propagate native execution control before ordinary compatibility fallbacks.
A pre-turn refusal after ephemeral receipt registration and causation binding
clears both capabilities before propagation, including cancellation. The
native tests run actual dispatcher/SQL/lease boundaries with declared governance
hooks; they do not establish full Agent genesis, amendment approval or READY.

Standalone spawn shutdown likewise distinguishes cooperative restore-task
withdrawal from a cancellation carrier with native control provenance. It joins
the same accepted restore owner before propagating its original native denial;
ordinary restoration failures remain failures. The native regression declares
the accepted restore handle as component input, not complete Manager recovery.

Database recovery tests inspect the exact original operation/publication and
cleanup errors in the full explicit carrier chain and retain the same database
owner. Selecting only the cleanup exception as an immediate cause would erase
part of that finite evidence. The inception cases keep the actual SQLite file
and connection owned while retirement is uncertain, then physically close in
test cleanup; the lightweight Hold backend contract test is not native PG
retirement proof. These stronger assertions do not waive uncertain cleanup.

The scheduler lock-expiry fixture refreshes its activity snapshot while its
original blocker transaction keeps the row unchanged. It observes only waiters
blocked by that exact session. A deliberately pre-warmed snapshot and bounded
setup-overlap cases exercise the observer instead of depending on the first
poll's timing. PostgreSQL documents transaction-local activity caching and
[snapshot refresh](https://www.postgresql.org/docs/16/monitoring-stats.html).
Production lease checks, expiry and native retirement deadlines are unchanged.

Endpoint-launched reindex jobs publish through the existing agent background
owner and canonical original-preserving Task wrapper. Publication accepts fresh
coroutines, not borrowed Tasks; refused Task creation closes unstarted work.
The job retains its original control privately for subsequent polling while
the agent retains its bounded terminal receipt. Neither public error strings
nor a completed Task certify reconciliation. The existing 32-job limit refuses
new publication when only live or control-bearing jobs remain; mutable business
status cannot retire a physically pending owner. Ordinary caller withdrawal
remains cancellation, not successful background completion. Native tests run
actual PostgreSQL/pgvector reindex writes and batched loopback SDK traffic;
Task-factory observers forward actual Tasks, including an earlier cancellation
observer, without fabricating completion. These remain component inputs, not
registered Agent READY or authenticated HTTP acceptance. Reconcile, synchronous
compatibility and remaining HTTP/CLI/lifecycle sites stay open in the cumulative
ledger; none of these local checks constitutes independent release approval.

The native SDK acquisition/retirement test compares lifecycle events and the
actual pending native-close Task's join dependency instead of demanding SDK
startup within one second. A delayed local transport exercises that distinction;
the complete test still has a finite 30-second deadline including cleanup.
Both implementation and fixture observe and join the actual native Task. No
production SDK, storage or shutdown deadline is extended by this test change.

Reindex job projection also observes its original Task when cancellation occurs
before the body takes its first step. The existing Agent shutdown helper cancels
and joins that accepted owner; public reads and pruning derive terminal state
from its actual receipt even when an earlier Task-factory observer runs before
publisher callbacks. Once observed, repeated polls do not manufacture new
business-progress timestamps. Native control remains private and unprunable;
ordinary unstarted cancellation becomes a terminal, reclaimable job.

The operator embedding CLI uses the existing owned-database retirement boundary,
passing its original body receipt. Native import/open control cannot become a
connection-error exit, and unsuccessful close admission or physical retirement
cannot leave a successful body result as the CLI outcome. Native tests run the
actual CLI in its own event loop with a real SQLite connection, independent
read-only observation, joined workers and an actual retired PostgreSQL lease
receipt. Lookup/callback failures are explicit component fault boundaries, not
proof of complete Agent startup, operator authentication or production recovery.

Telemetry publication honors that same fresh-coroutine contract. Refusal cannot
retry an operation already closed by the canonical Agent publisher; a proxy-owned
publication also uses the canonical Task constructor. Native control and caller
cancellation propagate, while ordinary advisory refusal retains coalesced refresh
flags for a later explicit event without scheduling a retry loop. An invalid
publisher return is an interface error, not a native publication acknowledgment.
These component checks construct the actual proxy but do not initialize a child
or certify READY, observer-executor retirement, or the remaining isolated-runtime
admission/quarantine boundaries in the cumulative ledger.

The unrelated backup/restore and privacy-persistence unit fixtures have explicit
scope too. Backup fixtures disable provider embeddings and refuse provider
resolution; their finite ten-second cleanup window is not a change to the
production one-second SQLite worker policy. The delayed-close case still runs
the actual native close and joins its original worker after a failed observation.
The timestamp-coercion branch test remains SQLite with a declared dialect input,
not native PostgreSQL restore acceptance. Privacy-persistence fixtures initialize
the actual Agent with every mandatory sovereignty feature and no optional feature
catalog or sync service, rather than spending its five-second shutdown fair share
on unrelated optional workers. Unknown-COMMIT purge errors remain fail-closed;
no production shutdown or purge budget, control classifier or outcome is relaxed.

Snapshot upload retirement uses the existing native close owner, opting into
retaining the opening cancellation and original close error together. Refused
close admission retains the exact unstarted client; repeated caller withdrawal
joins the accepted closer rather than cancelling it. Snapshot, target-loop and
periodic-loop normalization cannot turn that debt into a failed-result value.
Shutdown retains the same failed worker for repeated observers. Ordinary HTTP
availability errors with successful retirement retain their failed-result
behavior. Native loopback HTTPX/httpcore/SQLite tests cover these transitions;
they do not establish public-service/TLS deployment or Agent READY acceptance.

Canonical SOUL reads, seed promotion/refresh, graph linking and database-backed
bootstrap configuration preserve native storage control before legacy fallback.
Private identity ciphertext is written as bytes to BLOB/BYTEA, and timestamp
parameters as native UTC database values, while provenance remains ISO text.
Legacy SQLite text ciphertext is still readable. Disposable-key PostgreSQL and
SQLite round trips and post-COMMIT release-ACK fault cases prove these helper
boundaries, not complete Agent genesis, inherited-constitution policy or READY.

Native response retirement retains each failed resource and its original close
task even when the SDK has already set an optimistic closed flag. Repeated
shutdown joins that task; it does not retry the close or erase unresolved debt.
Ordinary caller cancellation after a successful close is not cleanup failure.
Retention pruning after a successful snapshot uses the same native close owner
and control classifier as the upload itself; it cannot consume shutdown
cancellation as a `prune_error` annotation on an otherwise successful result.
The Agent's finite snapshot/stop guard stops observation, not physical ownership:
it retains the exact original Task through canonical retirement debt instead of
closing the coroutine joining a native client. Its existing lifetime retains
each eventual original failure, including distinct concurrent snapshot/stop
failures. Timely completion uses the canonical owned-Task receipt too, so an
earlier exception reader cannot consume a cancelled Task's original carrier.
The finite tail retains each actual observer cancellation, including repeated
withdrawals, alongside native close failures; it does not reduce them to a
boolean or substitute a child's cancellation. Reporting preserves an original
callback cancellation even when physical close succeeded and its explicit
cause is an ordinary HTTP error. Explicit shutdown completion joins pending
original owners without
cancelling them, rejoining completed owners, or joining self/actual ancestors.
Neither a timeout, an observer notification nor a resource label is a close ACK.
All Agent terminal-inventory entry paths preserve original carriers by default,
including a native snapshot failure followed by refused stop-Task admission.
The immediate tail caller and later lifecycle completion observe the same full
evidence, not different exceptions with only copied resource metadata.
Physical continuation completion is separate from observer withdrawal: an
ordinary retained cancellation is reported to the public waiter only after
cleanup joins, and cannot cancel the completed owner or prevent retry of a
withdrawn cleanup observer. Native execution control still fails closed before
serving-record release; a successful independent close cannot clear its debt.

Memory consolidation, forgetting and paired graph-node deletion propagate native
storage control before ordinary report/zero-count/skip fallbacks. Episode cutoff
binds use the existing native timestamp adapter, and decay accepts native naive
UTC PostgreSQL datetimes as well as SQLite ISO text. Real PostgreSQL tests check
post-COMMIT release-ACK faults through the consolidator, MemorySystem and partial
Agent sleep helper, plus actual graph-node deletion with its episode row still
retained. These are native helper/consumer proofs, not full sleep/Agent READY or
external-provider acceptance.

RAG and governed semantic recall likewise propagate original native storage
control through ContextBuilder and ContextManager rather than rendering error
strings, unavailable metadata or warning sections as turn context. Native tests
exercise the authenticated locally-incepted identity and PostgreSQL ledger/RAG
paths with embeddings explicitly unavailable, not model or full READY acceptance.
Cold initialization, ingress release and reanchor cleanup preserve original
unknown/committed receipts ahead of cancellation. HTTP peer envelopes and
private ingress redaction carry only safe control/outcome classifications, not
private provider prose. Scheduler telemetry harvests cause-bearing cancelled
receipts before releasing the publisher task and latches them for readiness.

Stream lifecycle inheritance requires the actual constructing producer task;
a copied ContextVar in a sibling cannot confer privacy-frame reentry. Text
taps retain the original producer agent, admission scopes and request generation.
A TTS consumer cannot substitute its own agent or a replacement request with the
same opaque ID. Waiting for tapped text holds no privacy mutex; each native
synthesis validates original producer custody and fresh privacy policy. Direct
realtime cognition admission reads durable constitutional restrictions and the
completed hash-bound governance receipt before minting a session.
Captured constitutional validators are repeated before result/credential
publication as well as native dispatch. A tapped HTTP response retains the
same request generation through every outer forwarding layer's EOF and close.
Later revocation cannot replace an original failed native closer's debt with
an unowned denial.

Scheduler admission owns its original short database mutation through the
native COMMIT acknowledgement. Stop is reported after that owner settles and
before any scheduled effect begins; genuine commit uncertainty is preserved.
`execution_denial_scopes(error)` reports exact original scope provenance only
when all explicit authority carriers are scoped and none carries commit
uncertainty. Combining runtime and occurrence denials retains both scopes;
an unscoped authority error is never reclassified as occurrence-only retirement.

PostgreSQL moves only its native transaction exit and pool reset into original
owned completion tasks. Transaction bodies, context-manager yields and token
resets remain in the caller; arbitrary resolvers and gates are not shielded.
The strong native contract accepts an actual asyncpg pool. A caller-context
wrapper must cooperate through `PostgresPoolAdapter(pool, wrapper)`: `wrapper`
is an async context-manager factory receiving Core's managed native checkout;
it enters that manager and yields the same connection. Wrapper entry/exit and
their ContextVar tokens stay in the original caller. Core independently retains
and settles the registered native lease, even if wrapper exit omits it or tries
to suppress its terminal control. Arbitrary wrapper awaits remain cancellable.
Opaque legacy acquire wrappers retain ordinary caller-context behavior but
cannot admit execution custody, including custody introduced later inside an
initially unbound operational session. This restriction is explicit, not an
inferred native capability or a bypass of wrapper accounting.
The direct epilogues must be the actual native asyncpg context types, not
context-affine subclasses. A wrapper cannot suppress the original body failure
inside its managed lease: Core records it before invoking wrapper exit, and
does not publish after-commit callbacks for a rolled-back cancellation. After
the entire wrapper exit (including any post-reset await), all retained scopes
are revalidated at the final publication boundary.

Before issuing a committed receipt, one fixed `SELECT 1` on that same held
transaction proves it is not aborted: PostgreSQL can otherwise accept COMMIT
as a silent ROLLBACK. The proof is cancellable and precedes native commit
handoff. The proof itself is not acceptance of COMMIT: ordinary work revalidates every
retained admission after that awaited probe and immediately before native exit
ownership, without another await. Retirement at this boundary rolls the body
back; fixed native cleanup retains its separate post-retirement contract.
Known-commit custody must also own the top-level transaction, not
merely release a savepoint inside a wrapper's external transaction. Custody,
callbacks and fixed cleanup require this proof. Unfenced,
callback-free transactions retain their historical behavior but do not mint a
known-commit receipt without proof. Refusal to create an epilogue owner aborts
only its original native connection, retains the exact resource with no owner
as physical-retirement debt, preserves the original body error explicitly,
and denies the participating scopes. It is not a successful reset/rollback or
permission to retry. A failed native reset likewise aborts that original dirty
session; abort failure remains explicit evidence. The borrowed pool is never
terminated as a substitute for retiring its one lease.
Actual rollback/reset failures preserve the original body cancellation and
closer errors as explicit carriers. Failed physical reset denies every
participating scope even if no commit occurred. Error aggregation separately
retains the bounded unresolved-commit classification of legacy carriers; a
settled acknowledged receipt cannot erase unrelated reconciliation debt just
because the selected exception object changes.

`NativeExecutionObserver` is a passive, original-lifetime inventory for hosts
that hand off cancellation-resistant external providers. Bound observation
adds no execution scope or capability. PostgreSQL reserves the actual checkout
before acquisition can suspend and records only actual transaction-exit/reset
owners, before creating those tasks. Closing new observation admission cannot
cancel those epilogues. `join_accepted()` joins their physical owners and backend
classification independently of the provider's later continuation or exception
suppression; it preserves its own observer cancellation separately.

Classification notifications are not native ACKs or closers. Records remain
open across transaction exit and reset registration. A still-open acquisition,
transaction/operational body or adapter remains explicit resource debt, not an
unbounded provider join or successful physical retirement. Actual committed
facts and hidden UNKNOWN/failed-closer evidence survive alongside that debt.
Successful records are released promptly; unresolved resources remain retained.
The resource strongly retains its original checkout task and every actual
participating body task, including children using an inherited operational
lease. Completed participants are released by their actual task completion;
physical checkout completion removes the remaining participant roots and
callbacks. A detached child cannot disappear while its transaction/debt is
still rooted. Bind observation
before acquiring the original operational/transaction lease. A later observer
on an inherited or already-open unobserved connection is refused before SQL,
not silently attached to an empty inventory. Script SQL uses the same raw
transaction-control refusal as single-query SQL.
The cutoff also applies to NEW work on an already-retained connection.
Explicit transactions revalidate both original custody and observation after
checkout/operational-mutex waits, immediately before native BEGIN; savepoints
revalidate before native entry too. An already-accepted original exit/reset is
cleanup, not a new work admission, and is still physically joined.
An unscoped legacy autocommit query retains autocommit semantics (including
CONCURRENTLY DDL): observation owns its checkout/reset, not a fabricated
explicit-transaction COMMIT receipt. Opaque pools and raw transaction-control
SQL cannot bypass observation. Ordinary unobserved legacy paths are unchanged.
Native aggregation preserves an original enclosing cancellation when its
explicit cause would otherwise be selected; it never creates a reverse cause
edge or drops that cancellation just to avoid a cycle. A failing COMMIT also
retains the original observer cancellation alongside its native failure.
PostgreSQL opts its original epilogue tasks into `create_owned_task`'s
`retain_originals=True` policy at creation, before asyncio can reduce a caused
native cancellation to its cause. Generic task owners keep their established
cleanup-error priority; opting in grants no work or cleanup authority.
Errors or cancellation in wrapper code AFTER successful native reset carry
that same known commit receipt before classification, and all participating
scopes are sampled on that failure path too. They do not invent uncertainty on
healthy scopes merely because a wrapper stopped observing after retirement.
Cancellation while observing a successful native ACK is delivered on the
original cancellation object with an `AcknowledgedExecutionCommit`, not an
invented UNKNOWN. Its commit owner and shared original-reset record are
physical evidence, not an admission or a new generation. The checkout retains
one latest ACK task; earlier escaped receipts observe the same reset owner
without retaining every completed transaction in a long operational session.

After ACK/reset, authority loss is checked even when the caller was cancelled.
Only actual denied scopes retain the known-committed fact; healthy inherited
scopes are not poisoned. `execution_denial_scopes` returns an empty tuple for
a fully retired observer-only receipt, original scopes for a settled scoped
denial, and `None` for pending retirement, UNKNOWN, failed closers, legacy
unresolved commit carriers or any combined unscoped control. A known commit
must never hide another original unscoped failure. These facts remain control
evidence through wrappers and shutdown; they do not imply the whole external
effect completed or permit retry without durable reconciliation. Logical task
name prefixes aid tracing; the native owners are distinct tasks and names grant
no authority. Genuine native ACK/reset/rollback failures still fail closed.

Renewal teardown cooperatively stops the interval and physically joins its
in-flight native transaction before releasing the original advisory exclusion.
Concurrent cognition terminalization callbacks share one exact original-token
owner; its successful receipt prevents a late callback from manufacturing debt
by repeating a CAS against a token already cleared by that same owner.

`PostgresBackend.advisory_locks(..., on_loss=callback)` yields an exact-session
`AdvisoryLease` (or `None` for an empty, unobserved exclusion set). Registering
the callback is part of acquisition. `require_live()` rejects physical session
death, a detached asyncpg pool proxy, and completed retirement. A replacement
session cannot revive that capability. Callbacks are synchronous and invoked at
most once; hosts must synchronously latch denial and their fatal-loss policy.
Callbacks are notification, not instantaneous distributed fencing: asyncpg can
queue them after PostgreSQL has already released the lock.

### Terminal physical barriers (#3739)

`PostgresBackend.advisory_locks(TerminalAdvisoryBarrier(((namespace, key),)))`
uses the **same** bounded advisory allocator, exact-session loss listener,
original native closer and joined checkout/reset owner. The immutable request
requires nonempty signed-32-bit integer pairs (not booleans) and exclusive mode.
It requires the original already-connected backend and shared advisory owner;
retirement or replacement while waiting cannot admit a body on a successor.
It does not connect a replacement operational pool or expose a SQL executor,
connection, arbitrary terminal callback, target claim or provider permission.

The yielded `TerminalAdvisoryLease.require_physical()` proves only that exact
physical exclusion is still live. Its `require_live()` **always denies** ordinary
execution, including through `AdvisoryExecutionFence.require_work()` and
`lock_and_validate()`. The immutable request is itself an always-denying fence,
bound before allocator entry and retained through native retirement. Connection
initializers, loss callbacks, reset owners, the body and copied children all
retain that cleanup-only custody even when the caller had no original scope.
The loss listener explicitly rebinds its original scope union: asyncpg dispatches
from the transport's creation context, so a session first warmed for an ordinary
lease must not lend that unrestricted context to later terminal callbacks.
Native tests reuse that exact warmed session before externally terminating it.
The scope and physical handle retire monotonically; escaping a copied context does
not keep the permission alive. Ordinary advisory handles retain their previous
`require_live()` behavior.

This physical barrier can run behind retained denied or UNKNOWN ancestors; it
neither clears them nor restores ordinary work. All original admissions are
sampled again only after acquisition/body failure, exact-session retirement and
native pool reset have joined. Original control, native failures and actual
caller withdrawals are composed through the canonical finite error contract.
If the original backend/shared owner retires during asynchronous pool creation,
the exact newly owned pool closes through the same backend close owner before
refusal returns. Failed or refused close admission retains its exact pool/Task
debt; it is not a hidden replacement pool or successful retirement.
Hosts must still join their own exact accepted provider/storage/receipt Tasks
and validate original durable operation/target permission in a **fixed terminal
API**. A fresh mutex is not that permission, a producer join, an erasure receipt,
a reconciled COMMIT or a billing settlement.

`test_terminal_advisory_barrier.py` exercises actual isolated PostgreSQL locks,
denied/UNKNOWN ancestors, eager/ordinary children, ordinary-work refusals,
copied scope retirement, actual init/loss/reset callback children, session loss,
a one-slot operational pool, delegated backend retirement during checkout and
pool creation, and repeated withdrawal during acquire/body/release tails.
The existing original-advisory admission/physical-retirement tests also run the
terminal request, retaining real native protocol tails and failed closer debt.
These are native Core boundary proofs, not downstream Frinz adoption, deployed
object erasure, provider/GPU acceptance or published-package evidence.

`bind_execution_custody(fence)` owns one connection-free admission. Its host
`ExecutionFence` supplies immutable generation binding, `require_work()`, and
`lock_and_validate(connection)`. Copied children retain the same irrevocable
revocation state. A normal context exit retires that admission too. Foreign
turn executors carry the admission through the declaration-site turn registry;
binding a snapshot cannot discard a denying ancestor already on that task.

Native PostgreSQL queries validate using the actual mutation's connection and
transaction, before graph/file locks. Autocommit work becomes a short guarded
transaction only when custody is bound. Explicit transactions retain authority
locks through commit. Every query surface participates, including reads,
RETURNING, batch and script execution; SQL verbs cannot reliably classify
whether a query mutates. Validators must lock authority rows (FOR SHARE for
non-key generation updates), check the original identity/owner/generation, and
hold those locks through commit. They must not acquire a second connection,
commit the transaction or publish effects. SQL transaction-control statements
cannot escape a guarded native transaction. SQLite cannot silently execute a
PostgreSQL-authorized scope.

Tool dispatch checks admission after awaited permission hooks, immediately
before execution, and again before publishing its result. Already submitted
remote effects cannot be recalled by cancellation or process termination;
destination-side fencing is required for a stronger external guarantee.

The context owns no connection between operations. A stream retains its
original admission membership across consumer handoff, foreign continuation
and cleanup. A later consumer may add live scopes but cannot silently discard
an earlier retired/denying scope; reopening work requires a newly admitted
operation, not reusing that suspended stream. Children from a retired admission
cannot inherit its replacement. Consumers must join all owned work before
normal advisory retirement. Cleanup does not grant new cognition/tool/storage
authority; terminal identity/token CAS needs its own explicit native custody.

Failed advisory retirement also owns the original native session through its
physical exit. A synchronous asyncpg `terminate()` only aborts the local
transport; it does not prove that PostgreSQL has released the exclusion. Both
advisory APIs use the same owned native closer on failure: cancel/join pending
protocol work, send Terminate and await server EOF. A refused or failed closer
retains the exact original connection and Task (or no admitted Task) as cleanup
debt. A detached proxy never authorizes closing a successor checkout.

Finite public/fleet manager drains collect original observer withdrawals
through the canonical lifecycle observer, including entry serialization,
handoff seals, quarantine/refund joins, reconciliation and unsealing. The
collection is caller-local and used only for isolated terminal composition;
shared bounded source latches and later observers inherit no caller history.
Legacy boolean lifecycle observation remains compatible when no collection is
requested. This changes neither native commit classification nor retry rights.

The native provider service retains the owning agent's runtime custody and
checks each adapter attempt and streamed chunk, including decision discovery,
pin canaries, decisions, embeddings and each internal retry after backoff.
`await_execution_work(owner, operation)` evaluates a lazy operation only after
binding original runtime custody and rechecks it before publishing a result.
Public streams pin the union of every consumer's admission through exceptions,
fallback and finalization, without leaving a binding installed across a yield.
Cancelled or explicitly closed hosted streams finalize under cleanup-only
denial; ordinary usage writes and billing callbacks cannot run there. Explicit
control errors bypass ordinary accounting even for unbound consumers. Ordinary
provider failures with live original authority still record
failed-attempt and known partial-usage accounting. Codex transport readers have a neutral
transport-lifetime context; each tool callback still binds its owning turn.
Authority errors are not provider failures and must never trigger fallback. The AgentManager
accepts a trusted per-agent `execution_custody_factory` before construction;
it also preserves an explicitly bound shared backend and refuses replacing
that binding. Multi-tenant hosts should use an unbound shared operational pool
and inject independent per-agent custody through the factory.

The built-in standalone PostgreSQL server explicitly creates one
`ProcessRuntimeExecutionFence` per agent construction. This declares only the
original process-owned runtime lifetime: it is not a tenant row, distributed
generation or scheduler occurrence. Cold boot checks the launching occurrence
as well, while published resident services retain only the original runtime.
Shutdown retires that local lifetime before yielding. It never retires borrowed
tenant/shared-backend custody; multi-tenant hosts must supply their own native
generation factory. Provider construction validates and binds the original
custody first, and manager-supplied services reuse native agent usage storage.
Both AgentManager and the no-manifest single-agent startup branch supply this
original lifetime before provider construction. Failed single-agent startup
retires it before the real boot coordinator's first rollback await and before
awaiting the owned LLM-service close, including cancellation;
SQLite startup remains unbound. Native startup regressions exercise this
production selection rather than injecting an agent's custody afterward.

Host inception and birth replay may open only their exact local
`kestrel_prime.db` through a private lexical identity-anchor capability. It
retains the SAME original admissions, never drops an ancestor, and expires
irreversibly after the owned database closes; retained handles and copied
children cannot reacquire it. Exact archive reads require the native cold-read
backend. This does not authorize tenant SQLite, arbitrary paths, or general
PostgreSQL bypass: runtime birth replication still validates the destination's
original generation on its actual PostgreSQL transaction. Native file safety
is checked before granting anchor access: symlinks, hard links, directories and
other non-regular leaves retain the public file-validation refusal without

pending until physical close finishes; terminal host retirement joins it before
closing borrowed storage. Provider is_closed flags alone are not physical-close

it does not need a new collector Task to recover a successful private result. Inception,
embedding/recall compatibility fallbacks and modality accounting preserve native
control receipts before ordinary error/cancellation normalization; uncertainty
cannot authorize another INSERT, vector rewrite or legacy retrieval retry.

selection, not recovery from a caught authority error: it creates no scope,

reader caches cannot hide revocation, uncertainty or scoped cleanup-only
admission; ordinary unbound vector reads still use their original factory.

Memory-context retrieval retains those same originals: index DDL,

unproven, committed or debt-bearing control cannot take that local path.
Original scoped calls join their writes before context
publication. Legacy unbound callers keep background behavior, but later reads,

admission closes the refused coroutine and cancels/joins accepted siblings.

## Bounded observation is not native settlement
