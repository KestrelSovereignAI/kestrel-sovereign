# Launch Copy Drafts

This folder holds the current landing-page copy drafts for the Kestrel open-source launch.

## Files

- `LANDING_PAGE_WIREFRAME.md` — full landing-page wireframe with section-by-section copy, proof points, CTA guidance, and implementation notes.
- `SIMPLE_LAUNCH_PAGE_ONE_SCREEN.md` — a tighter one-screen version for a minimal launch page.

## Intended Use

- Start with `LANDING_PAGE_WIREFRAME.md` if the team wants a proper public page with clear sections.
- Start with `SIMPLE_LAUNCH_PAGE_ONE_SCREEN.md` if the team wants a fast, minimal page that can ship with low implementation overhead.
- Treat these as copy drafts, not final design or engineering specs.

## Source Constraints

These drafts are aligned to the current launch framing already visible across:

- the canonical message stack in issue #603 comments
- the open-core boundary proposal in issue #612
- the preview-packet/send language in issue #188
- the current README opening in the repo

## Positioning Guardrails

- Keep `Sovereign AI` as the category frame.
- Do not let the page read like a feature release.
- Do not over-index on the product family; keep Kestrel as the foundation.
- Use Caprock as proof of seriousness, not as the headline.
- Keep the first-screen message emotionally legible before it becomes technical.
