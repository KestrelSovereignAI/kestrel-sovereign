# Core 0.53.31 — Private native HTTP admission

Status: candidate; publication and artifact verification remain required.

The native HTTP hook retains each send's original validator inventory privately
before request observers run. HTTPX request extensions remain descriptive and
cannot replace that admission before remote dispatch. This applies to both
supported HTTPX generations, SDK retries, redirects and shared-client calls.

Loopback HTTP and real SQLite policy/effect regressions reproduce requests
escaping retired policy when observers clear or replace extensions, then require
zero remote effects with the private admission. Original scope retirement still
fails closed. Existing native retirement and receipt ownership are unchanged.

This corrects the upstream integration finding in Provider PR25's review227,
within Core #3569/#3385 and the ongoing Frinz adoption chain. Core 0.53.30's
publication/signature/source receipts remain valid; they do not waive this later
dispatch finding or the downstream release/live gates. No private Provider
workaround, metered request, production database or catalog mutation is used.
