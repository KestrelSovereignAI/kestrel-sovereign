# Core 0.53.35 — Original Future and Task custody

Status: candidate; product merge, release review, CI, publication and artifact
verification are required.

Core can physically join protocol-only and read-only asyncio Future-like
producers without assuming they accept private metadata writes. Exact native
Task/Future storage and the original task-bound admission receipt preserve
Core-created custom Task ancestry and retained outcomes; a forwarding facade
cannot borrow the underlying Task's metadata capability.

Postaccept publication failure must not lose an accepted Task or start its
payload. A direct caller receives that exact failed-gated Task when no explicit
receipt was requested. Explicit receipt callers retain raise-plus-receipt
behavior; true allocation refusal remains synchronous. Terminal-cache and
unstarted-close failures preserve original UNKNOWN and source cancellation
without rewriting shared source error graphs. An unstarted original is closed
once, including callbacks that register before raising. These changes are the
subject of [Core #3733](https://github.com/KestrelSovereignAI/kestrel-sovereign/pull/3733).

The release also includes the already-merged encrypted-store rotation recovery
changes in [Core #3730](https://github.com/KestrelSovereignAI/kestrel-sovereign/pull/3730)
and installed public MCP 0.7 permission/lifecycle integration gates in
[Core #3731](https://github.com/KestrelSovereignAI/kestrel-sovereign/pull/3731).
Rotation remains an internal, single-maintenance-owner service with quiesced
legacy writers and both original keys retained; it is not online cutover or a
working host command. MCP integration coverage is not full conformance,
vendor OAuth, or A2A interoperability acceptance. The SDK remains in its
existing 0.39 compatibility window.

Component verification covers actual Tasks and Futures, ordinary/eager task
factories, allocation/publication/close refusal, repeated cancellation and
native PostgreSQL readback. The A2A expiry fairness regression separately
bounds its deliberately hung row and covers delayed acknowledgement after
real receiver cancellation; healthy work keeps the unchanged production
deadline ([Core #3735](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/3735)).
The structural scheduler-restart test reuses the shared actual-worker close
schedule instead of requiring ordinary WAL close I/O to meet a wall-clock
latency assertion. Native-close/worker-exit blocking, failure and cancellation
controls retain real worker joins and restore the clock. Combined repeated
caller cancellation and late native error/UNKNOWN retain the original sources
through canonical composition after physical joining; no original graph is
rewritten. Production close budgets and their explicit expiry tests are
unchanged. The original CI close
delay remains unattributed ([Core #3736](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/3736)).
This candidate is not a claim that the private
Frinz catalog rollout, lifecycle financial settlement, coordinated account
erasure, live Kite LoRA/Ollama dogfood, or paid provider benchmarks are complete.
The separately owned computer-use epic remains independent of this rollout.
