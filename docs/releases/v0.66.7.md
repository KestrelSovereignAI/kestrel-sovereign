# 0.66.7 — Native MCP custody foundation

Candidate release notes. Publication and complete Task capability acceptance
remain separate gates.

- Reserve encrypted Task custody before a declaring tool call, under the
  actual selected handler, original permission, decided arguments, captured
  Tool contract and admitted OAuth authorization generation.
- Commit original-method Input and Task claims together. Retire both claims
  atomically when the current continuation is proven never sent; retain
  uncertain sends and commit acknowledgements without replaying the tool.
- Retain original registration owners through post-policy checks, required
  audit and deferred publication. Input authority verifies the current running
  handler rather than a copied or ended execution context.
- Preserve native control errors and uncertain outcomes when a local-state
  observation fails. Use one canonical Input settlement implementation for
  ordinary and coupled writes.
- Align the worker's complete dependency lock and Core wheel hash with this
  release and the public SDK 0.55 contract.

This foundation is private. Public Task configuration and capability
advertisement remain disabled while observation authority, wait providers,
native update/cancel operations, pending Apps delivery and full native/browser
acceptance are completed. Activation also requires the published official MCP
SDK fix for [python-sdk #3866](https://github.com/modelcontextprotocol/python-sdk/issues/3866).
MCP continues to use the published official SDK.

The remaining work is tracked in
[#3684](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/3684)
and [epic #3679](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/3679).
