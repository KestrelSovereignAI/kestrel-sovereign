# 0.64.1 — cold tool-effect imports

Candidate release notes; publication, deployment health and downstream
acceptance remain separate gates.

- Fix the Core 0.64.0 import cycle that replaced ordinary effect failures
  with an ImportError in a cold interpreter (Core #4003).
- Resolve existing agent invocation/registration metadata only when the
  corresponding tool operation executes, not while effect modules initialize.
- Leave the public agent package and its eager initialization unchanged,
  preserving its names, types, canonical identities and import synchronization.
- Keep lightweight tool-effect entrypoints independent of streaming startup;
  preserve original ordinary and uncertain terminal failures.
- Add fresh-process regressions for all three affected effect modules,
  terminal classification, canonical exports, star imports, simultaneous
  two-thread/all-export access and mixed public/named implementation imports.

No effect authorization, provider admission or recovery policy is widened.
This patch is not evidence of completed Runpod/LoRA live Kite dogfooding or
healthy production deployment.
