# 0.66.8 — Native MCP Task observation

- Supply the original installation's OAuth client identity during agent
  startup so background Task reads can verify it independently of a browser
  session.
- Tie each native Task read to its original connection, OAuth grant and tool
  contract. Bound concurrent reads and preserve terminal outcomes only after
  checking the original authorization again.
- Keep maintenance reads bounded. The local chat wait provider reports Task
  status without disclosing remote result content or restarting a stopped wait.
- Update the visual worker lock to match the Core 0.66.8 wheel.

This release adds private infrastructure for [MCP Tasks #3684](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/3684).
Public Task activation still requires the completed operator and App flows,
conformance checks and the fix in the [official Python MCP SDK](https://github.com/modelcontextprotocol/python-sdk/issues/3866).
