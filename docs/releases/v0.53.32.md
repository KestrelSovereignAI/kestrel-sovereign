# Core 0.53.32 — Atomic stream-owner construction

Status: candidate; publication and artifact verification remain required.

Owned iterator construction retains the exact producer and cancellation watcher
before every callback publication, including the initial completion callback.
Construction failure transfers those same accepted Tasks to the existing async
cleanup boundary and joins them before returning; it never starts a replacement.

A failed native start gate retains its original error before another publication
or pre-first-step cancellation can replace it. Compound constructor and physical
join errors use fresh canonical evidence instead of changing original causes.
The real privacy-lock factory hands the same failed native Task back to its
consumer without stranding a foreign-frame dependency. All Core async stream
handoffs use the canonical asynchronous constructor, including both HTTP routes
and lazy GenAI forwarding, so partial-constructor cleanup is not caller-specific.
Lazy GenAI forwarding retains the creator's original context instead of borrowing
the context of a later consumer after the original scope has ended.
Native SQLite regressions cover all constructor stages, ordinary and eager Task
factories, and original ordinary/UNKNOWN/COMMITTED evidence with zero body effects.

This corrects the public-Core integration findings from Voice PR30 review236,
within Core #3678/#3569 and Frinz #774/#664. Core0.53.31's verified release receipts
remain valid; they do not waive these later constructor findings. Voice and Frinz
must adopt the actual public corrected release before final approval or rollout.
No provider call, production database, identity, or catalog mutation is required.
