# Core 0.53.33 — Wait-worker resident custody

Status: candidate; review, CI, publication and artifact verification are required.

The mandatory WaitFeature now publishes its fallback reconciliation worker using
the existing first-party resident-runtime handoff. It waits for actual READY
publication and retains the same immutable runtime generation, rather than the
temporary request/advisory admission used during agent initialization. Ordinary
effect children still inherit every original caller admission and remain denied
after that admission retires. Generation retirement and feature shutdown continue
to stop the original worker; no replacement authority or weakened health policy
is introduced.

The defect surfaced during Frinz's nonempty dev-candidate check: metadata loading
completed, then a fallback tick retained a retired boot admission in the shared
wait reconciler, poisoning later scheduler ticks and failing strict host health.
A native PostgreSQL regression drives the actual initialization/READY boundary,
WaitFeature worker and reconciler with the canonical schema. It verifies work
after boot-admission retirement, denial of an ordinary copied child, subsequent
cron reuse, and original runtime/feature retirement. This focused component test
is not a complete application boot or live-rollout acceptance claim.

Tracks existing Core #3385 and Frinz #774/#664. The verified 0.53.32 artifacts
remain retained; Frinz must adopt the corrected public release and repeat its
live nonempty recovery gates before promotion. No paid model calls or catalog
changes are needed to reproduce this defect.

Minimum-version conformance also retains native hook cancellation evidence on
Python 3.11: timed hooks use a lexical deadline on their original owned task,
without a hidden timeout child that can lose a stronger terminal receipt.
Deep structured audit payloads that exceed the decoder's recursion limit are
withheld before truncation. Component tests use task-preserving deadline guards
and place simulated crashes after actual renewal acknowledgements; they neither
fabricate those acknowledgements nor downgrade uncertain commits. These paths
receive an explicit Python 3.11/native-PostgreSQL gate as well as the ordinary
full unit and integration lanes.
