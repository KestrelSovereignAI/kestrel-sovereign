# Core 0.54.1 — upgrading a co-hosted host from 0.53

Core 0.54.1 is the first published 0.54 release; the 0.54.0 tag was withheld.
It replaces the draft A2A protocol with native A2A. Its published release
notes are the GitHub release for `v0.54.1`. This file records an upgrade
requirement found after publication (#3872).

- A host that serves two or more agents needs `KESTREL_BASE_URL`. Core 0.53
  defaulted it to `http://localhost:8888`; native A2A publishes only an
  explicit URL and never uses the listen address. Without it the host reports
  healthy, but no agent publishes a native interface and every co-hosted A2A
  task, message, question and stop fails when an agent first sends it.
- For a local or self-hosted host add `KESTREL_BASE_URL=http://127.0.0.1:<port>`
  with no path, using the `[host]` port from `multi_agent.toml`, and
  `KESTREL_A2A_PUSH_ENABLED=false` to the project `.env`, which `kestrel start`
  reads. Co-hosted sends poll; push delivery needs `KESTREL_DATA_KEY` and a
  process identity.
- Later releases log one startup warning when such a host lacks the variable,
  report it in `kestrel doctor`, and name it in the send-time error.

The [offline cutover runbook](../architecture/a2a/OFFLINE_CUTOVER.md#start-the-native-host)
covers the full upgrade. Public Cloud Run publication is #3819.
