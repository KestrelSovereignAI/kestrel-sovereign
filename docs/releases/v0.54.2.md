# 0.54.2 — attended feature-recovery startup boundary

Candidate release notes; publication and downstream acceptance are separate
gates, not established by this file.

- Extend preboot host-readiness transfer with `maintenance=True`: real feature
  construction and READY, without releasing Core resident/business startup.
- Bind an immutable complete `expected_features` inventory for maintenance
  lifecycle verification. Missing, extra, disabled or unspecified inventory
  cannot certify repair, including an internally consistent empty registry.
- Hold inline A2A startup, session-start hooks, sync/salvage startup, Scheduler
  schedule changes and Delivery in-flight recovery. Refuse ordinary turns and
  ready-hook completion throughout that generation, even after SafeMode exit.
- Keep native lifecycle verification, constitutional attestation, durable exit
  CAS, original execution custody and physical retirement requirements intact.

Participating external features must honor the same policy before inline
claims. Workflows 0.7.7 adds that startup behavior. This is not an arbitrary
third-party-code sandbox or a completed Frinz recovery operator. See
`docs/architecture/MAINTENANCE_FEATURE_RECOVERY.md` and Core #3827.
