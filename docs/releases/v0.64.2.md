# 0.64.2 — truthful shutdown deadline observations

Candidate release notes; publication and deployment remain separate gates.

- Include the merged cold tool-effect import fix from PR4007. The immutable
  0.64.1 tag failed its normal release gate and was never published to PyPI.
- Correct two shutdown-test timing proxies exposed by that release gate
  (Core #4008), without changing production timeouts, owners or admission.
- Drive real durable owner heartbeats through the store's explicit UTC clock;
  verify the actual timer policy and peer recovery against committed SQLite
  rows, not wall-clock delays between test continuations.
- Observe the wait bound passed for the exact original storage-close Task.
  Control the pre-close deadline with the existing loop-clock fixture, then
  physically join the same worker and all original native cleanup owners.
- Reuse one transparent wait observer, retaining native input validation,
  cancellation and outcome identity. Lifecycle checkpoint deadlock guards
  remain real-thread bounded while production loop deadlines are controlled.

No failed check is waived or retried unchanged, no warning is suppressed, and
the failed 0.64.1 tag is not overwritten. This is not evidence of completed
Runpod/LoRA Kite dogfooding, healthy production deployment, or a fix for the
separate worker-shutdown warnings tracked by #3734.
