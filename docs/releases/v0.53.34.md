# Core 0.53.34 — Sovereignty retrieval and portable conversations

Status: candidate; release review, CI, publication and artifact verification are required.

Sovereignty retrieval now supports an explicit output-byte bound and provenance
policy. A real CID cannot be satisfied from another tenant's shared host cache
when local-cache lookup is denied. Blocking retrieval retains its physical
operation until completion, including repeated cancellation and native-control
failure; releasing an awaiting task is not proof that its SDK thread has stopped.
These changes shipped to main in #3701.

Conversation export writes logical content and rendered fields inside the
existing encrypted CAR archive, rather than carrying source-host at-rest
ciphertext into the destination. Import prepares all conversation fields through
the destination store's canonical encryption policy before destructive history
replacement. Timestamps, sessions, model/provider and metadata are retained.
Legacy encrypted envelopes must authenticate using the actual destination key;
unreadable cross-key or corrupt data fails before replacement. This does not
implement signing-key or agent-identity migration.

The sovereignty adapter also accepts an explicit, validated import-journal
namespace. Its default remains `agent_import_log`; embedding applications can
select their own Core-owned table without colliding with a different host schema.
Journal initialization and writes fail closed, and every required audit write
must acknowledge exactly one affected row. If import and audit both fail, the
canonical error composition retains the original failure, cancellation and
native-control evidence. These changes shipped to main in #3725.

Component verification includes real encrypted CAR/AEAD and SQLite round trips,
isolated PostgreSQL schemas, cross-key rejection, required audit acknowledgements,
and original-control/cancellation evidence. Both product PRs passed their full
CI and independent full-diff reviews. This candidate still requires its own
release gates and published-wheel verification. It is not a claim that the
private Frinz catalog rollout, live Kite dogfood, remote LoRA quality checks or
paid provider benchmarks have completed.
