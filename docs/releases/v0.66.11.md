# 0.66.11 — Original host-resource ownership

- Expose bounded host-resource lending through the existing owned-task gate.
  Reserve before native allocation, lend the exact original Task before its
  payload starts, and retain the original admission through physical retirement.
- Preserve captured authority, detachment and cleanup boundaries across Agent,
  privacy, callback and streaming paths. A copied Context does not grant work.
- Keep uncertain construction, missing completion capture and failed physical
  source retirement fail-closed; preserve original errors and resource receipts.
- Enter physical-retirement phase at the admitting frame, so database disposal,
  rollback drains, retained SQLite closers and HTTP disposal require no new WORK
  capacity. Connection acquisition and statements remain WORK.
- Qualify native CPython and uvloop constructors without scanning unrelated
  live Tasks on ordinary successful loans. Configured or substituted factories
  are not accepted for host loans.
- Export the canonical cancellation-keeping Lock/Condition acquisition helper
  for host accounting retirement. This finishes existing cleanup before its
  caller's withdrawal is delivered; it grants no Work or new Task ownership.

Hosts implement the public lender protocol and retain their original receipts.
Core's one-shot publisher is the sole caller of the host retirement callback;
host drain loops may join and read-only reconcile, but must not independently
retire a reservation. Existing hosts require no lender binding unless they
adopt this protocol. Frinz's native host adoption is tracked separately in
[Frinz #834](https://github.com/KestrelSovereignAI/frinz/issues/834).

See [the public ownership contract](../development/ASYNC_OWNERSHIP_PUBLIC_API.md)
and [Core #4164](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/4164).
