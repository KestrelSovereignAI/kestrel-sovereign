# Core 0.53.28 — Hosted execution custody

Status: unreleased; review and full release gates remain required.

This patch extends the native execution contract for hosted runtimes
([#3569](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/3569)).

- Exact-session advisory leases carry irreversible physical-loss/retirement
  state into scheduler effect admission and existing renewal-loss handling.
- Host-authored generation fences are validated on native storage's actual
  mutation transaction, with authority locks before graph/file locks and fixed
  transaction custody membership through commit.
- Agents/backends retain their original runtime binding across background,
  child and foreign transport tasks. Tools recheck after permission and result
  hooks; failed parallel batches drain owned siblings before retirement.
- Hosted SQLite/SQLAlchemy execution fails closed. Cleanup retains denial and
  permits only fixed existing-identity Stop settlement. Completed effects
  without durable checkpoints remain unresolved rather than cleanly complete.
- Reanchor distinguishes committed/uncertain commit outcomes from rollback,
  enters SafeMode and requires reconciliation before retry or cognition.

No new authority pool, provider fallback, host migration or downstream live
acceptance is implied. Frinz must install its schema-specific immutable binding
and adopt the verified published artifact before its rollout can be accepted.

See [Storage Architecture](../architecture/storage/STORAGE_ARCHITECTURE.md#hosted-execution-custody)
for the contract and executor limitations.
