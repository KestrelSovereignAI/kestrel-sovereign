# Core 0.53.28 — Hosted execution custody

Status: unreleased; review and full release gates remain required.

This patch extends the native execution contract for hosted runtimes
([#3569](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/3569)).

- Exact-session advisory leases carry irreversible physical-loss/retirement
  state into scheduler effect admission and existing renewal-loss handling.
- Host-authored generation fences are validated on native storage's actual
  mutation transaction, with authority locks before graph/file locks and fixed
  transaction custody membership through commit.
- Agents/backends retain their original runtime binding across background,
  child and foreign transport tasks. Tools recheck after permission and result
  hooks; failed parallel batches drain owned siblings before retirement.
- Hosted SQLite/SQLAlchemy execution fails closed. Cleanup retains denial and
  permits only fixed existing-identity Stop settlement. Completed effects
  without durable checkpoints remain unresolved rather than cleanly complete.
- Reanchor distinguishes committed/uncertain commit outcomes from rollback,
  including pool release/reset cancellation; enters SafeMode and requires
  reconciliation before retry or cognition. Invocation settlement and scheduler
  exception normalization preserve unresolved commit evidence.
  Single-query, batch and script pool retirement carry that evidence and latch
  further work denial in the original admission, even when legacy code catches
  the exception. Joined parallel children retain uncertainty over ordinary errors.
- Provider attempts/chunks and parent invocation publication retain original
  custody, including decision discovery/canaries, embeddings and internal
  provider retries after backoff; fallback cannot normalize authority denial.
  Stream handoffs retain monotonic membership through finalization, aborted
  hosted accounting stays cleanup-only, and Codex readers do not retain the
  first turn's retired admission.
  Each forwarding iterator's close joins underlying provider cleanup. Provider
  send and isolated RPC boundaries recheck after setup/wake/traffic waits;
  decision/embedding accounting, EOF settlement and deferred boot readiness
  preserve original custody through their final awaits.
- PostgreSQL scheduler dispatch durably marks the exact occurrence before an
  effect. Uncertain execution is held for reconciliation, never automatically
  replayed after advisory-session loss. Renewal retains runtime and effect custody.
  Pause preserves unresolved occurrence identity; resume and definition changes
  refuse unresolved effects until reconciliation.
- Bound durable-signal boot builds/repairs its exact sequence index transactionally;
  unbound host maintenance retains concurrent DDL.

No new authority pool, provider fallback, host migration or downstream live
acceptance is implied. Frinz must install its schema-specific immutable binding
and adopt the verified published artifact before its rollout can be accepted.

See [Storage Architecture](../architecture/storage/STORAGE_ARCHITECTURE.md#hosted-execution-custody)
for the contract and executor limitations.
