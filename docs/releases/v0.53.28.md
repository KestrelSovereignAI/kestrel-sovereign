# Core 0.53.28 — Hosted execution custody

Status: unreleased; review and full release gates remain required.

Native close, refund, dispatcher-writer and cancelled-write handoffs retain
their exact accepted Task through callback-publication failure, including eager
execution. Unstarted work cannot become a retirement ACK; independent cleanup
still runs. Manager lock release follows actual acquisition, and shutdown
observers retain their actual withdrawal without modifying shared source errors.

Additional terminal-boundary corrections preserve irreversible checkpoint and
active-stream cancellation evidence, including repeated task-result reads and
later ordinary closure failures. AgentManager validates original custody before
provider construction. The built-in standalone PostgreSQL host declares an
original process-owned runtime lifetime for cold resident services, separate
from occurrence/tenant authority; shutdown retires only its own local lifetime.
Manager-supplied native LLM services bind storage-owned usage before consumers.

This patch extends the native execution contract for hosted runtimes
([#3569](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/3569)).

- Exact-session advisory leases carry irreversible physical-loss/retirement
  state into scheduler effect admission and existing renewal-loss handling.
- Host-authored generation fences are validated on native storage's actual
  mutation transaction, with authority locks before graph/file locks and fixed
  transaction custody membership through commit.
- Agents/backends retain their original runtime binding across background,
  child and foreign transport tasks. Tools recheck after permission and result
  hooks; failed parallel batches drain owned siblings before retirement.
- Hosted SQLite/SQLAlchemy execution fails closed. Cleanup retains denial and
  permits only fixed existing-identity Stop settlement. Completed effects
  without durable checkpoints remain unresolved rather than cleanly complete.
- Reanchor distinguishes committed/uncertain commit outcomes from rollback,
  including pool release/reset cancellation; enters SafeMode and requires
  reconciliation before retry or cognition. Invocation settlement and scheduler
  exception normalization preserve unresolved commit evidence.
  Single-query, batch and script pool retirement carry that evidence and latch
  further work denial in the original admission, even when legacy code catches
  the exception. Joined parallel children retain uncertainty over ordinary errors.
- Provider attempts/chunks and parent invocation publication retain original
  custody, including decision discovery/canaries, embeddings and internal
  provider retries after backoff; fallback cannot normalize authority denial.
  Stream handoffs retain monotonic membership through finalization, aborted
  cancellation/close accounting stays cleanup-only, explicit controls bypass
  ordinary accounting even when unbound, and Codex readers do not retain the
  first turn's retired admission.
  Each forwarding iterator's close joins underlying provider cleanup. Provider
  send and isolated RPC boundaries recheck after setup/wake/traffic waits;
  decision/embedding accounting, EOF settlement and deferred boot readiness
  preserve original custody through their final awaits.
- PostgreSQL scheduler dispatch durably marks the exact occurrence before an
  effect. Uncertain execution is held for reconciliation, never automatically
  replayed after advisory-session loss. Renewal retains runtime and effect custody.
  Pause preserves unresolved occurrence identity; resume and definition changes
  refuse unresolved effects until reconciliation.
- Bound durable-signal boot builds/repairs its exact sequence index transactionally;
  unbound host maintenance retains concurrent DDL.
- A2A stores reuse native runtime storage (also for DSN-only agents), while
  inbound authorization and peer tools preserve original custody and wrapped
  control evidence. Operational sessions retain participating admissions through
  physical release and successful-release publication checks. Stream closure and
  timed-out hosted usage writers are joined; late inline Codex errors reach the
  original turn sink. Cold scheduler preparation is durably marked before boot,
  so uncertain bootstrap preserves its original occurrence for reconciliation.
- Forwarded turns retain privacy-lock reentry and the requested session, while
  ordinary child wakes queue for their own conversation turn.
  Actively advancing stream close makes cleanup-only denial visible before
  source cancellation; wrapped non-streaming control errors bypass ordinary
  classification, accounting, retry and fallback. Scheduler markers sample
  expiry after acquiring the exact claim row, while conservative confirmed
  deadlines and an independently joined watcher close stalled-renewal gaps.
- The original confirmed deadline fences cold preparation as well as dispatch;
  expiry cancels and joins bootstrap before any stale readiness publication.
  Outer adapter retry, decision discovery/canary/timeout, subagent and failed-wake
  boundaries preserve wrapped control evidence. Failed streaming checkpoints
  cannot replace an irreversible outcome. Ordinary still-authorized decision
  and embedding failures retain their original-admission usage accounting,
  as do ordinary streaming-provider failures and their known partial usage.

- Explicit resident ownership keeps a successfully published cold runtime's
  monitors alive after its launching turn retires, without refreshing its
  immutable generation or relaxing ordinary child/foreign-turn denial.
  Feature-owned peer restoration starts after READY under that same resident
  root; replay subscriptions, terminal joins and retries survive the boot
  occurrence. Newly committed outbound-question subscriptions use the same
  resident contract, after caller-admitted POST/store publication; arbitrary
  effect children retain their requesting turn.
- Normal stream EOF leaves queued child turns runnable; abort/close failure
  still fails closed. Assistant persistence, audit hooks and embedding fallback
  retain irreversible control evidence. Default native LLM accounting reuses
  the storage-owned PostgreSQL executor before first boot consumers.
- Durable cognition's explicit control outcomes become exact-token FAILED,
  including cause-chained cancellation and typed Stop/self-fence carriers;
  non-retryable and non-ACKable, including late retained outcomes; no ordinary
  release/retry may erase uncertain effect evidence.
  Failed terminal writes retain cleanup debt and prevent clean owner release;
  fixed existing-owner liveness cannot revive stopped owners or admit work.
  Ordinary at-least-once crash recovery and database-outage limitations remain.

- Isolated deferred/legacy ingress and ACK/retry completions retain their first
  native control receipt before completed-task removal. One strongest receipt
  denies later ingress and survives physical proxy retirement; successful ACK
  responses recheck their original admission. Ordinary live retries are unchanged.
- Late facade/health/lifecycle ownership retains first native control evidence
  past cancellation grace, including neutral foreign-loop categories without
  retaining private source errors. LLM cleanup bounds its joins and hands off
  exact unfinished operations while attempting independent resources; pending
  work remains explicit cleanup debt and storage waits for its writers.
  Agent, Feature and A2A background owners retain one strongest receipt instead
  of accumulating completed exception graphs.

No new authority pool, provider fallback, host migration or downstream live
acceptance is implied. Frinz must install its schema-specific immutable binding
and adopt the verified published artifact before its rollout can be accepted.

Actual agent storage and local host-key retirement now wait behind the exact
LLM writers, even after the bounded close hands cleanup to a continuation.
Failed construction retains unpublished providers before awaiting cleanup;
pending or uncertain native closure blocks replacement birth and shared-pool
retirement. Native control receipts survive server cancellation/group handling.
Terminal host drain joins physical unpublished-provider close ownership;
failed Agent initialization retains its complete resource owner, and a failed
host-key database factory transfers its actual retirement owner into Agent
cleanup. Lifecycle consumers join continuations even when shutdown returns a
cancellation-containing group. Fleet/quarantine and delegated results preserve
the original strongest native receipt after completed-task removal rather than
replacing it with cancellation, text, or a new aggregate wrapper.
Durable cleanup heartbeat re-arm works before late retention/debt registration,
without refreshing denied authority. Late cognition groups are classified before
owner removal, and spawn tools do not normalize a distinct child's denial into
an ordinary failed result while the parent remains live.

See [Storage Architecture](../architecture/storage/STORAGE_ARCHITECTURE.md#hosted-execution-custody)
for the contract and executor limitations.

Startup batch/admission and native PostgreSQL rollback now preserve the original
strongest control receipt after independent cleanup. Repeated heartbeat/result
reads keep bounded original tracebacks. Private inference renewal validates its
original scopes after lock acquisition, and bounded host close retains physical
remote-client drainage. Rotated/unpublished clients share canonical native-close
ownership, so uncertain retirement cannot be retried as a fresh native close.

Host inception and SQLite-to-PostgreSQL birth replay retain original custody
through an exact, expiring local identity-anchor capability. Ordinary tenant
SQLite remains denied and runtime replication keeps native generation fencing.
Birth embeddings/accounting borrow that same owned database and physically
retire providers before closing it. Privacy persistence/restoration, constructed
Agent/batch rollback, isolated config CAS and lifecycle joins preserve original
native control instead of reporting an ordinary refusal, retry or cancellation.
Retained lifecycle reads and deadline handoffs remain bounded; terminal client
retries serialize physical ownership rather than inherit a concurrent failure.

Confirmed scheduler occurrence expiry no longer fails shared-host readiness when
the original typed denial has no commit outcome, runtime denial or native close
debt. Expired admissions stay denied; fresh work can proceed. Upstream
after-commit callbacks and embedding diagnostics retain canonical control,
including cancellation/group carriers after a real committed write.
