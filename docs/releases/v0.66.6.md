# 0.66.6 — Cloud Run update preservation

Candidate release notes; publication, deployment health and downstream
acceptance remain separate gates.

- Omit the fetched immutable revision name when applying a new configuration,
  allowing Cloud Run to generate a distinct revision rather than rejecting an
  update with HTTP 409.
- Preserve unmanaged nested container configuration as well as the outer
  Service: database socket mounts, startup/liveness/readiness probes, ingress
  protocol, command/arguments, name and resource flags/unknown limits. The
  profile still owns its image, complete environment, ingress port number,
  CPU/memory limits and declared template scaling/timeouts/concurrency.
- Refuse unsupported sidecar/multiple-port ambiguity and explicit conflicting
  probe ports before dispatch. Do not silently erase another container or reset
  a probe to make an update succeed.
- Require the Cloud Run SDK 0.15.0 readiness-probe contract. The normal lock
  already resolves 0.15.0; this corrects the declared minimum without upgrading
  unrelated dependencies. Hosted unit execution retains the cloud extra and
  preflights its actual SDK imports so provider regressions cannot disappear
  through module-level import skipping.

Source changes: [#4171](https://github.com/KestrelSovereignAI/kestrel-sovereign/pull/4171)
and [#4174](https://github.com/KestrelSovereignAI/kestrel-sovereign/pull/4174).
This is a normal new patch release, not a replacement or retag of 0.66.5.

Production [#3340](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/3340)
remains open until the exact released artifact passes zero-traffic application
health, authenticated original-DID readback and deliberate serving verification.
Preserve original identity/custody, numeric secret versions, database attachments
and instance bounds. The completed database upgrade and secret repair must not
be repeated or replaced by a new identity setup.

This release does not resolve original host-resource lending in
[#4164](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/4164),
complete Frinz catalog adoption, or establish live LoRA/Ollama/Kite acceptance,
GPU cold-start timing or cost. Private Frinz/catalog packages are not public
package releases.
