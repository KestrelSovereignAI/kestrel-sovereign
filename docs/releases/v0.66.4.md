# 0.66.4: feature installs survive `kestrel update`

- **The host manifest records feature installs and removals**
  ([#4127](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/4127),
  [#4148](https://github.com/KestrelSovereignAI/kestrel-sovereign/pull/4148)).
  `kestrel feature install` and the console's install append an entry for the
  installed copy to `.kestrel-host-features.toml`. The entry follows where
  that copy came from: its checkout, `pypi = ""` for an index install, or the
  no-source entry for a git install. The append leaves the rest of the file as
  written. A console remove takes the entry out again. Before this release,
  the next `kestrel update` on a source checkout ran `uv sync`, which removed
  a package installed this way, and nothing put it back.
- **`kestrel update` refuses, before it pulls, to uninstall an extension that
  nothing reinstalls.**
  - It asks uv what the sync will remove
    (`uv sync --dry-run --output-format json`, on the project files as the
    incoming revision records them).
  - It counts a package as kept when the host manifest declares it, when an
    agent's `features` allowlist would reinstall it, or when a package that is
    reinstalled requires it.
  - The refusal names each package and prints the entry that records it.
    `--continue-on-error` downgrades it to a warning.
  - The update that first pulls this release still runs the old install step,
    so it does not check. Record any extension installed with
    `kestrel feature install` before that update. On a host with no manifest,
    `kestrel feature sync --capture` does this.
- **Windows journey harness**
  ([#4130](https://github.com/KestrelSovereignAI/kestrel-sovereign/pull/4130)).
  It walks a fresh Windows install the way a new user does: quickstart, chat,
  the Telegram channel, stop and start, `kestrel update` with the host down
  and up. It runs weekly and on demand, and is not a required check.
- **The deprecated `heartbeat_*` HealthFeature tool aliases are removed**
  ([#4133](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/4133),
  [#4147](https://github.com/KestrelSovereignAI/kestrel-sovereign/pull/4147)).
  Use `health_check`, `health_history` and `health_interval`. A typed
  `!heartbeat` command is unchanged.

Not in this release:
- The restart coordinator's `update_then_restart` does not run the new
  update check yet
  ([#4146](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/4146)).
- Follow-ups from the final review of #4148 are tracked in
  [#4149](https://github.com/KestrelSovereignAI/kestrel-sovereign/issues/4149).
